# Описание архитектуры и взаимодействия компонентов

Документ подготовлен для защиты курсового проекта по дисциплине «Разработка мобильных приложений».

---

## 1. Общая архитектурная схема

Приложение построено с использованием многослойной архитектуры (Layered Architecture), разделяющей ответственность между представлением, бизнес-логикой и слоем работы с данными:

```
┌────────────────────────────────────────────────────────┐
│                   UI Layer (Widgets)                   │
│   Screens: Dashboard, Projects, Achievements, Skills   │
│   Widgets: StatCard, ProjectCard, SkillProgressBar     │
└───────────────────────────▲────────────────────────────┘
                            │ (Events & State Listeners)
┌───────────────────────────▼────────────────────────────┐
│              Business Logic & State Layer              │
│       PortfolioProvider  │   ThemeProvider (Provider)  │
└───────────────────────────▲────────────────────────────┘
                            │ (Repository Contract: ApiService)
┌───────────────────────────▼────────────────────────────┐
│                   Data & API Layer                     │
│  ┌──────────────────┐ ┌──────────────────┐ ┌────────┐  │
│  │  HttpApiService  │ │FirebaseRestServ  │ │ Cache  │  │
│  │ (Node.js REST)   │ │(Firestore REST)  │ │(Shared)│  │
│  └────────▲─────────┘ └────────▲─────────┘ └────────┘  │
└───────────┼────────────────────┼───────────────────────┘
            │                    │
            ▼                    ▼
     [Node.js Server]    [Google Firebase Cloud]
       (Express API)       (Cloud Firestore DB)
```

## 2. Назначение и функции слоев

### 2.1. Слой представления (UI / Presentation Layer)
- **Framework:** Flutter (Material Design 3).
- Состоит из независимых экранов (`Screens`) и переиспользуемых виджетов (`Widgets`).
- Виджеты являются реактивными (Reactive UI): они подписываются на изменения состояния через контекст (`context.watch<PortfolioProvider>()` или `context.read<PortfolioProvider>()`) и автоматически перерисовываются при изменении данных.
- **Экраны:**
  - `HomeDashboardScreen`: агрегирует статистику, отображает ключевые проекты и достижения.
  - `ProjectsScreen`: обеспечивает просмотр каталога, полнотекстовую фильтрацию и поиск.
  - `ProjectEditScreen`: форма ввода с двухсторонней валидацией данных.
  - `AchievementsScreen`: отображение наград с разделением по категориям.
  - `SkillsScreen`: визуализация уровня освоения компетенций (Progress Bar).
  - `ProfileScreen`: визитка студента, переключатель режимов API и темы.

### 2.2. Слой управления состоянием (State Management Layer)
- Реализован с помощью официального пакета `Provider` (`ChangeNotifier`).
- **`PortfolioProvider`** инкапсулирует:
  - Текущие списки проектов, достижений и навыков.
  - Индикаторы состояния: `isLoading`, `isSaving`, `errorMessage`.
  - Поисковые строки и активные фильтры.
  - Методы CRUD (Create, Read, Update, Delete) для всех сущностей.
- **`ThemeProvider`** отвечает за переключение между светлой и тёмной темой с сохранением выбора пользователя в постоянную память.

### 2.3. Слой сервисов и доступа к данным (Service & Data Layer)
- **Паттерн «Репозиторий» (`ApiService`):**
  Определяет единый интерфейс взаимодействия с данными независимо от того, откуда они поступают.
- **`HttpApiService`:**
  - Отправляет асинхронные HTTP-запросы к Node.js REST API серверу.
  - Формирует корректные HTTP-заголовки (`Content-Type: application/json; charset=UTF-8`).
  - Анализирует статус-коды ответов (200, 201, 204, 400, 404, 500) и выбрасывает типизированные исключения при сбоях.
- **`FirebaseRestService`:**
  - Осуществляет прямое взаимодействие с облачной базой данных Google Firebase Cloud Firestore через официальный REST API (`https://firestore.googleapis.com/v1/...`).
  - Транслирует Dart-объекты в формат типизированных полей документов Firestore (`stringValue`, `doubleValue`, `arrayValue`).
- **`LocalCacheService`:**
  - Реализует паттерн Cache-Aside на базе `SharedPreferences`.
  - Обеспечивает мгновенную загрузку данных при холодном старте приложения.
  - Позволяет приложению работать на 100% стабильно даже при отсутствии подключения к сети Интернет или в период недоступности бэкенда.

## 3. Модели данных (Domain Models)

1. **`StudentProfile`:**
   Идентификатор (`id`), ФИО (`fullName`), должность/направление (`title`), университет (`university`), факультет (`faculty`), учебная группа (`group`), средний балл (`gpa`), контакты (`email`, `phone`, `githubUrl`, `telegramUrl`), биография (`bio`), аватар (`avatarUrl`).

2. **`ProjectItem`:**
   Идентификатор (`id`), название (`title`), подробное описание (`description`), роль студента в проекте (`role`), статус реализации (`status`: «Завершен», «В разработке», «Планируется»), массив используемых технологий (`tags`), ссылки (`githubUrl`, `demoUrl`), период работы (`period`).

3. **`AchievementItem`:**
   Идентификатор (`id`), название (`title`), категория (`category`: «Хакатон», «Олимпиада», «Наука», «Сертификат», «Конференция»), организатор (`issuer`), дата получения (`date`), результат (`place`: «1 место», «Победитель», «Финалист»), описание (`description`).

4. **`SkillItem`:**
   Идентификатор (`id`), название (`name`), категория (`category`: «Hard Skills», «Soft Skills», «Инструменты», «Языки»), числовой коэффициент владения (`level` от 0.0 до 1.0), текстовая градация (`levelTitle`).

## 4. Обработка ошибок и отказоустойчивость

- Сетевые запросы обернуты в блоки `try-catch` с настраиваемым таймаутом (`ApiConfig.requestTimeout = 8 секунд`).
- При возникновении ошибки сети (таймаут, отсутствие соединения, недоступность сервера):
  1. Ошибка перехватывается, и пользователь видит ненавязчивое информационное уведомление (`SnackBar`).
  2. Приложение автоматически обращается к локальному кэшу, благодаря чему интерфейс не «зависает» и не показывает белый экран.
  3. Все пользовательские формы содержат валидаторы обязательных полей (`FormState.validate()`), предотвращая отправку некорректных данных.
