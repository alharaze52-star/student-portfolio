# Доклад и сценарий защиты курсового проекта

**Тема:** Разработка мобильного приложения для цифрового портфолио студента  
**Дисциплина:** Разработка мобильных приложений  
**Стек:** Dart, Flutter, Node.js (Express), Google Firebase API, GitHub Actions  

---

## 🎤 Сценарий выступления (3-4 минуты)

### 1. Введение и актуальность темы (30 секунд)
> «Уважаемые члены комиссии! Вашему вниманию представляется курсовой проект на тему: **"Разработка мобильного приложения для цифрового портфолио студента"**.  
> **Актуальность:** В процессе обучения студент накапливает огромное количество учебных проектов, научных публикаций, грамот за олимпиады и сертификатов о прохождении курсов. Часто эти данные разрознены или теряются. Созданное мобильное приложение решает эту проблему, предоставляя удобный инструмент систематизации достижений, демонстрации компетенций работодателям и быстрого формирования резюме».

---

### 2. Архитектура и технологии (1 минута)
> «Приложение разработано с использованием современного кроссплатформенного фреймворка **Flutter** на языке **Dart**, что позволяет компилировать единую кодовую базу в нативный код для **Android** и **iOS**.
> 
> **Архитектура решения:**
> - В качестве архитектурного паттерна выбран **Provider (ChangeNotifier)**, реализующий реактивный подход и строгое разделение UI-слоя и бизнес-логики.
> - Слой работы с данными реализован по паттерну **"Репозиторий" (Repository)** через абстрактный интерфейс `ApiService`. Это позволило поддержать сразу несколько источников данных:
>   1. Полноценный **Node.js REST API бэкенд** на Express;
>   2. Прямой доступ к облачной базе данных **Google Firebase Cloud Firestore** через официальный REST API;
>   3. Автономный локальный кэш на базе **SharedPreferences** для бесперебойной работы приложения в условиях нестабильного интернета.
> - Настроен непрерывный процесс сборки **CI/CD в GitHub Actions**, который автоматически компилирует и тестирует проект под iPhone (iOS) и Android».

---

### 3. Демонстрация работы с данными через API (CRUD) (1.5 минуты)
> *(Переходим к показу на смартфоне или эмуляторе)*:
> 
> 1. **Главный экран (Обзор):**  
>    «На главном экране мы видим визитку студента со средним баллом GPA, автоматический подсчет метрик (количество проектов, завершенные работы, число наград) и секцию ключевых проектов. Все эти данные получены через метод `GET /api/profile` и `GET /api/stats`».
> 
> 2. **Операция добавления данных (POST):**  
>    «Переходим во вкладку "Проекты" и нажимаем "Добавить проект". Заполняем форму: название, стек технологий, описание и ссылку на GitHub. При нажатии "Сохранить" отправляется запрос `POST /api/projects`. Обратите внимание: данные валидируются перед отправкой, а при успешном ответе карточка мгновенно отображается в списке».
> 
> 3. **Операция редактирования данных (PUT):**  
>    «Если мы хотим изменить статус проекта (например, перевести из "В разработке" в "Завершен") или обновить роль, открываем меню карточки, выбираем "Редактировать" и сохраняем изменения. Отправляется запрос `PUT /api/projects/:id`».
> 
> 4. **Операция удаления данных (DELETE):**  
>    «Удаление защищено модальным диалогом подтверждения от случайных нажатий. После подтверждения уходит запрос `DELETE /api/projects/:id`, и объект удаляется из базы».
> 
> 5. **Фильтрация и поиск:**  
>    «Реализован интерактивный поиск по ключевым словам и фильтрация проектов по статусу, а также фильтрация грамот по категориям (Хакатоны, Олимпиады, Наука, Сертификаты)».
> 
> 6. **Дополнительные возможности:**  
>    «Во вкладке "Навыки" наглядно отображаются Hard и Soft компетенции с уровнем владения в процентах. В профиле поддерживается переключение тёмной и светлой темы, а также генерация сводного текста портфолио для резюме».

## ❓ Ответы на возможные вопросы комиссии

**В: Почему выбран Flutter, а не нативная разработка на Kotlin / Swift?**  
*О:* Flutter компилируется напрямую в нативный машинный код (ARM), обеспечивает стабильные 60-120 FPS и позволяет поддерживать единую кодовую базу сразу для Android, iOS и Web с абсолютно идентичным UI, сокращая время разработки и поддержки в два раза.

**В: Как реализована защита от сбоев сети (offline mode)?**  
*О:* Реализован паттерн Cache-Aside. Любые полученные из API данные сохраняются в локальном хранилище. Если устройство офлайн или бэкенд временно недоступен, приложение не падает, а плавно загружает актуальный кэш и выводит предупреждение.

**В: Как работает сборка под iPhone на GitHub Actions?**  
*О:* В репозитории настроен GitHub Actions Workflow (`.github/workflows/ios-build.yml`), запускающийся на облачной виртуальной машине macOS. В процессе раннер скачивает Flutter SDK, выполняет `flutter pub get`, прогоняет тесты и собирает iOS-пакет с помощью команды `flutter build ios --release --no-codesign`, упаковывая готовый билд в артефакты сборки.
